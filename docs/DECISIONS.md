Record every non-trivial decision here: date, decision, alternatives considered, why.

| 2026-10-19 | Logprob provider: live mode goes through a Cloudflare Worker (`POST /api/next-tokens`) to Workers AI `@cf/zai-org/glm-4.7-flash` (`logprobs` + `top_logprobs`, thinking disabled, `max_tokens: 1`, KV cache per prefix, rate limit + daily cap). The Worker's upstream adapter also accepts any OpenAI-compatible `chat/completions` endpoint (same response shape). Default view and all tests use a recorded-fixture provider behind one interface `nextTokens(prefix, k) -> {token, logprob}[]`. Details: docs/llm-provider.md | OpenAI(-compatible) chat/completions with a key; in-browser transformers.js model as the live provider; Workers AI models without top_logprobs (e.g. qwen3-30b-a3b-fp8 only has prompt_logprobs) | CLAUDE.md prefers Workers AI if it returns logprobs: the published schemas of glm-4.7-flash and about 11 other Workers AI models include `top_logprobs` (0-20) with an OpenAI-shaped response. It uses the `AI` binding, so there is no third-party key. OpenAI needs a key and per-call cost. In-browser needs a ~134 MB download per user and ~0.6 GB RAM, which breaks "first step costs almost nothing" and is risky for the headless verifier on this box. Caveat: not yet verified by a live call because the box's CLOUDFLARE_API_TOKEN is rejected (malformed); the Worker phase starts with a one-call smoke test, and the fallback is the OpenAI-compatible upstream (key becomes a blocker) or the opt-in in-browser provider. |
| 2026-10-19 | Recorded sample format: one JSON file per garden in `src/samples/<id>.json` (bundled), `schemaVersion: 1`, `prompt`, `model` metadata, `k`, and a flat `nodes` map keyed by continuation text after the prompt (`""` = root) -> sorted top-k `{token, logprob}`. Bundling keeps the first view instant and offline. |
