## [Unreleased]

### Added

- `POST /api/structure` in the Worker, for the optional AI pass: it takes up to 200 redacted step summaries per batch and suggests labels from a fixed set (sub-question, hypothesis, evidence, dead end, decision, answer) and claim-to-evidence links, with GLM-4.7-Flash on Workers AI in JSON-schema mode (or any OpenAI-compatible server). Answers are schema-checked (unknown step ids and labels are dropped), cached by a hash of the batch, and share the rate limits and daily budget of the lens; no key is needed. `buildBatches` builds the batches from redacted text only, at most five per session.
- The website is now a showcase: "See how your coding agent got there." over the live map of the agents that built Reasontrail, a quiet switcher for the three samples (`?session=`), the skill install line, and How to read a map. "Map your own session" (`?view=open`, or drop a `.jsonl` anywhere on the page) reads a Claude Code, Codex or Grok Build session in a Web Worker in your browser, with progress and Cancel for big files, a 50 MB limit that points to the CLI, and calm messages for unsupported, empty or half-written files; nothing is uploaded. `?view=install` lists the skill and CLI commands, the same ones `--help` and `install-skill` use. After the first load the gallery and the drop zone work offline.
- Grok Build and Codex sessions: `npx reasontrail` now finds the newest session for the folder across Claude Code, Grok Build (`~/.grok/sessions`, `GROK_HOME`) and Codex (`~/.codex/sessions`, `CODEX_HOME`), and maps it the same way (Grok subagents become lanes). `--current` reads `CLAUDE_CODE_SESSION_ID`, `GROK_SESSION_ID` or `CODEX_THREAD_ID`; `--source claude-code|grok|codex` keeps to one store and `--list` shows all three side by side. `install-skill` now installs the skill for Codex too (`~/.agents/skills/reasontrail`). The Codex reader is built from the public format and not yet checked against a real session.
- Details on demand: Enter (or a click) on an episode or pattern opens a detail panel (a bottom sheet on phones) with the step list, the selected step by tool (a Bash command and its output, an Edit as a line diff rendered as text, a Read or Grep path and pattern, an Agent call with "Open lane"), the honesty label on the agent's own words, "thinking (text not stored)", and provenance with "Show raw" (the verbatim record, redacted in samples and shared copies) and "Copy link to step". Links reopen a step (`?step=` on the website, `#step=` in a file), Back and Forward follow them, and Esc returns focus to the map. Side trails expand in place; At a glance rows, "Where it got stuck" rows and "+n more files" select their target.
- The reasoning map's glance view, now the first view of the local viewer and the website: the task card with the honesty label, three "At a glance" rows, the route of up to 12 named episodes (length follows effort), subagents as side trails below it, numbered trouble blazes matched one to one by a "Where it got stuck" list, and the destination card with changed files, the last check and the agent's final words. One Tab stop with arrow keys, Home/End and `[` `]` through the patterns; a vertical route with a sticky destination bar on phones; the Outline stays one toggle away (`?view=outline`, `#view=outline` in a file). `?session=<sample>` opens another sample; garden links (`?sample=`) still open the next-token lens. Episode titles now name what was touched ("Read outline.ts +3 more", "Run lint and typecheck", "Delegate: Verify phase 12") and the last verification names only the check ("pnpm lint").
- Real sample maps of the agents that built Reasontrail: a verifier that fails a phase and the fix round that follows (three subagent lanes), an implementer that fails lint and typecheck and recovers, and a planner rewriting the plan after a change request. Each is trimmed, redacted and checked (`pnpm audit:samples`), bundled with no key needed, and rebuilt byte for byte with `pnpm samples:sessions`. The CLI gains `--trim <from>:<to>` to keep a stretch of steps.
- The `/reasontrail` skill for Claude Code (Grok Build reads the same folder): ask your agent to "map this session" and it opens the session's map and replies with the file path; `--share` makes a redacted copy. `reasontrail install-skill [--target claude|grok|codex|all] [--dry-run] [--force]` installs it, reports "unchanged" on a repeat run and never replaces a file you edited without `--force`. `pnpm skill:audit` and `pnpm skill:evals` (nine offline sandbox cases) check it. When `CLAUDE_CODE_SESSION_ID` names a session that is not found, the CLI now says so and uses the latest for the folder.
- Reasontrail CLI and local viewer: `node cli/dist/cli.mjs` (later `npx reasontrail`) turns the newest Claude Code session for the current folder, the calling agent's session (`--current`), or any path or session id into one self-contained HTML outline (task, route, trouble, outcome, honesty label) that works offline from `file://`. `--share` writes a redacted copy, `--json` prints the session graph, `--list` shows recent sessions. The project is renamed Reasontrail, with a new trail mark, wordmark and favicon; the seed mark lives on as the lens icon.
- First view: a bundled sample garden ("The old lighthouse keeper opened the door and") drawn as a tree of next-token branches whose thickness follows probability, with no key and no network.
- The "specimen plate" look: warm paper and moss-ink colours in light and dark themes (contrast and colour-blind checked), self-hosted IBM Plex Mono and Instrument Serif, the token-garden logo, wordmark and favicon, and a specimen label beside each garden showing its prompt, model, k and recording date. On small screens the garden scrolls sideways instead of shrinking its labels.
- The garden reads at a glance: branch thickness is the chance of each next token, a dashed "other tokens" stub shows the share outside the top-k, marker shapes and dash patterns tell grown, growable and not-recorded branches apart (never colour alone), hovering a branch shows its exact percentage and the path chance, a readout under the drawing spells the continuation being read, and a legend explains thickness and markers. Spaces and newlines in tokens are shown as `·` and `↵`. On phones the drawing opens at the first fork with a "Scroll sideways" cue.
- Explore the recorded garden: click a branch to grow or collapse it (the branch you clicked stays still while the tree reshapes, and only the new branches grow in, with no motion when reduced motion is on); a branch outside the recording shows a calm "Not in this recording." note without any network request. The address bar always reopens the fork you are reading (`?path=1.0`), "Copy link" in the header copies it, and a link that goes past the recording opens as far as it can with a short notice. Thick dashed branches keep real dashes.
- Keyboard and screen readers: the garden is one Tab stop and a real tree (arrow keys, Home/End, Enter/Space to grow or collapse), so even the thinnest branch is reachable and shows its percentage on focus; each branch is announced like "looked, 8.9 percent". A "Table view" lists every visible branch with the same numbers, a polite status line announces growth, not-recorded notes and copied links, and on phones the focused branch never hides under the sticky readout.
- Six recorded gardens (lighthouse, robot, language, autumn, recipe, cat) grown by SmolLM2-135M, each fully recorded two levels deep plus two paths six tokens deep, and a picker to switch between them by mouse or arrow keys. `?sample=cat&path=0.1` opens a fork in a given garden, an unknown garden falls back to the lighthouse with a short notice, Back returns to the garden you came from, and everything keeps working offline once loaded. `pnpm samples:record` re-records a garden locally.
- Temperature, sampling and uncertainty, with zero model calls: a temperature slider (0–2, presets 0 greedy, 1.0, 1.5) reshapes every branch's thickness and numbers at once, with an "approximate (top-k only)" note because only the top 5 were recorded; "Sample a path" walks the garden with a seeded sampler ("New seed" for another), highlights the path with an outlined accent stroke and diamond tips, and spells and announces the sentence and why it stopped. Each open fork shows its uncertainty in bits, the Table view adds Recorded, At T and Uncertainty columns, `?t=1.5&seed=7` reopens the same view, and a short "How to read this garden" panel explains it all.
- A Cloudflare Worker endpoint, `POST /api/next-tokens`, that returns a prompt's top next tokens with probabilities from Workers AI (`glm-4.7-flash`, thinking off), validates input (1–1000 characters, k 1–8, 4 KB body), caches every prefix in KV for 30 days so repeated branches cost nothing, and answers with calm, specific errors (400, 413, 405, 502, 503). Sample mode is unchanged and still needs no key.
- The live endpoint protects itself and its owner: per-IP rate limits (20 model calls and 120 requests per minute, 429 with `Retry-After`), a daily cap on model calls (`DAILY_UPSTREAM_CAP`, 503 `budget_exhausted`; cached branches keep working), a 10 s timeout with one retry on a 5xx, and a second upstream for any OpenAI-compatible server that returns `top_logprobs` (`UPSTREAM=openai-compatible`). `docs/EXTENDING.md` explains how to add a provider or upstream, record your own garden and retheme the app.
- Reasontrail's session model: `shared/session` reads a Claude Code transcript (with its subagent transcripts) on your machine and turns it into a typed, versioned step graph of steps, lanes and edges (next, result-of, spawned, forks), with the file and line of every step, tool categories and file touches, and counts of anything it could not read. No AI, no network, and the same input always gives byte-identical output.
- The step graph now says what happened: up to 12 named episodes per lane (user turns, exploring, editing, verifying, delegating, the answer), six detected patterns with their evidence steps (error streaks, retries, reverts, rewinds, interruptions, churn; each marked resolved or not), and the outcome: files changed with edit counts (shell writes such as `cat >`, `sed -i` and Python writes included; net-reverted files left out), the last test/build/lint/typecheck run and the final answer. All by rules, no AI.
- Redaction for anything shared: `redactGraph()` replaces secrets, tokens, keys, emails and home paths with typed placeholders and drops system records and environment dumps; `pnpm audit:samples` fails if a committed sample, fixture or skill eval still matches, or contains a term from your local, untracked `.redact-denylist`.
